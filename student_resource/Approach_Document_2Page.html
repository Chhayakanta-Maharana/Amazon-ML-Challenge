Business Entity Resolution: High-Throughput & Precision-Optimized Solution

Team: EntityResolvers AI  |  Competition: ML Challenge 2026  |  Validation Macro F0.5: 0.9934  |  Candidate Size: ~36.5 / entity

1. Executive Summary & Problem Overview

In enterprise data integration, business records from disparate sources arrive with severe textual noise, missing postal codes, legal suffix variations, and domain shifts (training: US, India; test introduces France). The objective is to identify all records from Source 2 and Source 3 matching deduplicated reference entities in Source 1 under Macro F0.5 (penalizing false positive merges twice as heavily as missed links and strictly rewarding singletons).

We present a two-stage Hybrid Multi-Channel Inverted Index Blocking + Pairwise HistGradientBoosting Classifier that processes ~10M records completely offline on standard CPU without external databases or geocoders. Our pipeline achieves a validation Macro F0.5 score of 0.9934 (Precision: 0.9958, Recall: 0.9840) while reducing the 1.73M × 9.97M comparison space to only ~36.5 candidates per entity (>99.9997% reduction), directly fulfilling the ranking bonus criterion for candidate minimization.

2. End-to-End Pipeline Architecture

Raw S1, S2, S3 → Country-Aware Normalization → 4-Channel Inverted Index Blocking → 25-Dim Feature Extraction → HistGradientBoosting (τ=0.85) → Validated TSVs

Core Technical Innovations:

  • Country-Partitioned Streaming: Records are partitioned by country (US, India, France). Comparison spaces are isolated naturally, eliminating cross-border comparisons, maintaining peak RAM < 2.5 GB, and guaranteeing zero cross-border false merges.
  • Channel-Hit Agreement Scoring: The blocking stage tracks how many distinct channels triggered a candidate pair (1 to 4), feeding this multi-channel intersection score directly as an engineered feature into the classifier.
  • Exact Macro F0.5 Optimization: Threshold grid search sweep directly on the official metric with singleton credit. Optimal threshold τ = 0.85 eliminates false merges while securing full 1.0 scores for singletons.

3. Scalable Candidate Generation (Blocking Strategy)

Comparing every record against every other record across ~10M entries is computationally impossible. We engineered 4 complementary inverted indexing channels designed to maximize recall ceiling while minimizing candidate set size:

  1. Alphanumeric Name Prefix Key: First 5 alphanumeric characters after legal suffix removal (captures typos at name endings and prefix alignment).
  2. Sorted Token-Pair Key: Lexicographically sorted first 2 non-stopword tokens (e.g. "Apollo Pharmacy" ≡ "Pharmacy Apollo"), ensuring invariance against word-order transpositions.
  3. Distinctive Name Token Inverted Index: Filters out generic corporate stopwords (services, tech, corp, pvt, ltd, group) and indexes high-specificity lexical tokens with fanout ceiling ≤ 150.
  4. Compound Address-Numeric Key: Combines numerical identifiers (building numbers, postal/PIN codes) with primary street tokens to capture entities with variant trade names at identical physical locations.
Blocking Performance: Reduced the search space by >99.9997%, yielding an average of only ~36.5 candidates per entity (capped at ≤50) with a validation recall ceiling of >99.4%.

4. Matching Model & Feature Engineering

4.1 25-Dimensional Pairwise Feature Vector

For each generated candidate pair, we extract 25 dense non-linear similarity features:

  • Name Similarities (7 features): Character Levenshtein ratio (name_ratio), Token Sort Ratio (name_sort_ratio), Token Set Ratio (name_set_ratio), Jaro-Winkler similarity (name_jw), Token Jaccard overlap (name_jaccard), normalized length disparity (name_len_diff), and exact string match (name_exact).
  • Address Similarities (9 features): Full address edit distance (addr_ratio), token set similarity (addr_set_ratio), address Jaro-Winkler (addr_jw), address token Jaccard (addr_jaccard), length discrepancy (addr_len_diff), exact address match flag (addr_exact), numeric & PIN code intersection ratio (num_overlap), and exact numeric set match (num_exact).
  • Structural & Interaction Features (9 features): Country match verification (same_country), field presence flags (has_name_both, has_addr_both), multi-channel agreement count (channel_count), multiplicative interaction (name_x_addr), max/min similarities (max_sim, min_sim), weighted similarity (weighted_sim = 0.55 * name + 0.45 * addr), and dual high-confidence indicator (both_high).

4.2 Model Type & Inference Optimization

  • Model Architecture: HistGradientBoostingClassifier (scikit-learn, MIT/BSD-3 license, <1M parameters, <1 MB disk size). Hyperparameters: max_iter=160, learning_rate=0.07, max_depth=7, min_samples_leaf=20, l2_regularization=0.1.
  • Batched Inference: Candidate features are scored in vectorized mini-batches (2,000 entities / ~60,000 pairs per matrix call), achieving an inference throughput of ~470 entities/second on standard CPU.
